# Plan: Finish the admin panel migration to Vue 3 + Inertia

## Goal

Make `/admin/*` a fully working Vue 3 + Inertia admin panel: every screen (including the login form) rendered by an Inertia page with the shop's design language, guarded by the `admin` guard, covered by feature tests — with no Bootstrap-3 leftovers anywhere.

---

## Current context / assumptions

**Stack (verified on disk, branch `dev2`, HEAD `9f24906`)**

- Laravel **12.1.1** (check with `docker compose exec -T roadrunner php artisan --version`), Inertia **v2**, Vue **3.5**, Vite 5, PrimeVue **4** (Aura preset with a sky-blue `#0284c7` primary defined in `frontend/src/main.js`), RoadRunner + Octane.
- Frontend sources in `frontend/src/`, pages auto-resolved by `import.meta.glob('./Pages/**/*.vue', { eager: true })` in `frontend/src/main.js`. Build into `public/build/` with `cd frontend && npm run build` (built assets **are committed to git**).
- Middleware is registered the Laravel-10 way: `bootstrap/app.php` binds `App\Http\Kernel`, so `app/Http/Kernel.php` is live. The `web` group includes `HandleInertiaRequests` and `ForceLogout`.
- Shared Inertia props (`app/Http/Middleware/HandleInertiaRequests.php`): `appName`, `flash.message`, `flash.error`, `auth.admin` (`['name' => ...]` or `null`), `userName`, `cart`.

**What already works (do not rewrite)**

| Piece | Where | State |
|---|---|---|
| Admin guard | `config/auth.php` → `admin` guard, provider `admins` → `App\Admin` | works |
| Guest → login redirect | `app/Exceptions/Handler.php::unauthenticated()` maps guard `admin` → route `admin.login` | works — verified live: `GET /admin` → `302` → `http://localhost/admin/login` |
| Admin route group | `routes/web.php:49-102` (`Route::prefix('admin')`) | works, but **no group middleware**; each controller adds `$this->middleware('auth:admin')` in its constructor |
| Admin controllers | `app/Http/Controllers/Admin*Controller.php` (8 files) + `Auth/Admin{Login,ForgotPassword,ResetPassword}Controller.php` | render Inertia pages with correct props |
| Admin pages | `frontend/src/Pages/Admin/**` (12 `.vue` files) | exist, all declare `defineOptions({ layout: AdminLayout })`, all use the correct Inertia `useForm`/`router`/`axios` calls |
| Shop-side precedent | `frontend/src/Pages/Orders.vue`, `Order.vue`, `Cart.vue`, `Components/ShopPagination.vue` | already PrimeVue (`DataTable`, `Column`, `Tag`, `Paginator`, `Button`) |
| Dev admin credentials | `database/seeders/AdminsTableSeeder.php` | `admin@admin.dev` / `password` (dev fixture) |

**What is broken / incomplete (the actual work)**

1. **The login screen is still legacy Blade.** `AdminLoginController::showLoginForm()` (line 23-26) returns `view('auth.admin-login')`, which `@extends('admin.admin')` — a Bootstrap-3 shell that loads `public/css/app.css` (Bootstrap **v3.4.1**), `public/js/app.js` (1 MB jQuery bundle) and `public/js/admin_script.js`. Verified live: `GET /admin/login` → 200 but the HTML is the legacy page, not Inertia. It is the only admin screen not on Vue 3.
2. **Every admin Vue page is styled with Bootstrap class names that no longer exist.** Bootstrap was removed from the Vite bundle in commit `75602a7`; `frontend/src/assets/app.css` contains no `.btn` / `.form-control`. Yet the pages use `btn btn-primary`, `btn-sm btn-outline-*`, `form-control`, `form-select`, `form-label`, `table table-responsive`, `row g-4`, `col-lg-8`, `text-muted`, `text-end`, `alert alert-*`. Result: admin screens render as unstyled HTML. Verified by `grep -rnoE 'class="[^"]*(btn|form-control|table|col-|row)[^"]*"' frontend/src/Pages/Admin` (40+ hits).
3. **No admin tests exist.** `tests/Feature` has no `Admin*` test; `App\Admin` has no `HasFactory` and there is no `database/factories/AdminFactory.php`.
4. **Dead legacy code.** `resources/views/admin/*.blade.php` (20 files), `resources/views/auth/admin-login.blade.php`, `resources/views/auth/passwords/email-admin.blade.php`, `.../reset-admin.blade.php` are legacy. No route renders them any more — except `AdminShippingMethodsController::search()` line 60 `return view('admin.orders', ...)`, and that method is not routed either. `public/js/admin_script.js` is only referenced by `admin/admin.blade.php`.
5. **Duplicated styles (DRY).** All 10 page-level `.vue` files re-declare the same scoped `.content-card`, `.page-header`, `.page-eyebrow`, `.page-title` blocks.
6. **Fragile pagination.** `Admin/Shared/AdminPagination.vue` applies PrimeVue `p-button` class names to an Inertia `<Link>` and needs a `links` array. `Components/ShopPagination.vue` already does this properly with `primevue/paginator` and a Laravel paginator object — reuse that pattern.
7. **Login error handling gap.** `AdminLoginController::login()` returns `redirect()->back()->withInput(...)` with no `withErrors(...)`, so a wrong password shows an empty form.
8. **Wrong guard on the forgot-password form.** `AdminForgotPasswordController::__construct()` line 38 uses `$this->middleware('guest')` (the **web** guard) instead of `guest:admin` (compare `AdminResetPasswordController` line 42, which is correct).
9. **Stubs / missing screens (out of scope, listed so nobody "fixes" them blindly):** `AdminOrdersController::showEditForm()`/`update()` are empty (routes `/admin/show-order/{id}` and `PUT /admin/order` do nothing), `AdminUsersController::delete()`, `AdminShippingMethodsController::delete()/showEditForm()/update()` are empty, and several `JsonResponse|string` methods `return ''` for non-JSON requests.

**Environment / tooling reality (learned the hard way — read this before running anything)**

- **`php artisan test` runs against the DEV database and empties it.** `phpunit.xml` sets `DB_HOST=mariadb_test`, but the suite actually connects to `mariadb` (the `mariadb_test` container's `shop` schema has zero tables). `RefreshDatabase` truncates the dev data, so after the last test run you **must** re-seed: `docker compose exec -T roadrunner php artisan db:seed --class=DatabaseSeeder` → expect `catalogs=16 roots=4 properties=2 products=199` (admins are seeded too: `admin@admin.dev`).
- Tests only run inside the container: `docker compose exec -T roadrunner php artisan test --filter=<Name>`. Expect 2-3 `level=warning` lines about `compose.yaml`/`docker-compose.yml` before the real output — they are noise.
- **RoadRunner caches routes and the Vite manifest per worker.** After changing PHP routes or rebuilding assets run `docker compose exec -T roadrunner rr -c /etc/.rr.yaml reset` (prints `plugin reset: [http]`). Without it the browser keeps loading the previous `assets/main-*.js` hash.
- `docker compose` resolves `compose.yaml` (no bind mount, `.env.prod`) while the running container came from `docker-compose.yml`, and `compose.yaml` **comments out** the `mariadb` volume/port and the `mariadb_test` service. Never run `docker compose up -d` / `build`; only `exec`.
- There is **no JS test runner** in this repo (`frontend/package.json` has no `test` script, `tests/js` does not exist). Frontend verification = `npm run build` + real DOM inspection.
- The `browser_use` CLI on this machine is a broken symlink (its venv python is gone). Use headless Chrome instead:
  ```bash
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
    --no-sandbox --virtual-time-budget=9000 --window-size=1440,1100 \
    --screenshot=/tmp/admin.png --dump-dom "http://localhost/admin/products" > /tmp/admin.html
  ```
  then read `/tmp/admin.png` with `vision_analyze`. Without `--virtual-time-budget` the SPA renders blank.
- Long chained shell commands (git commit chains, `rr reset` + curl chains, `python3 -c`) can trip an approval prompt that stalls for 5 minutes. Prefer **one action per tool call**, use the container's `curl` (`docker compose exec -T roadrunner curl -s ...`) rather than host network calls, and put parsing logic in a script file.
- PHPStan is unusable repo-wide (pre-existing): `phpstan.neon` uses PHPStan 1.x keys but `vendor/bin/phpstan` is 2.1.7 → `Invalid configuration: Unexpected item 'parameters › checkMissingIterableValueType'`. Do not try to fix it here; mention it in the PR description.

## Architecture / proposed approach

Keep every controller, route name, prop shape and JS behaviour exactly as-is, and change only two things: (a) the *presentation contract* — one shared stylesheet `frontend/src/assets/admin.css` plus a small set of admin classes (`admin-card`, `admin-btn`, `admin-input`, `admin-table`, …) replaces every Bootstrap class name, with `AdminLayout.vue` and `AdminPagination.vue` rewritten as the two shared components; and (b) the *login entry point* — `AdminLoginController::showLoginForm()` returns `Inertia::render('Admin/Login')` instead of the legacy Blade view. Guard enforcement moves from eight controller constructors to a single `Route::middleware('auth:admin')` group so a new controller cannot forget it, and the whole thing is pinned by feature tests written before each change.

### Task 9 — `AdminPagination` on PrimeVue, like the shop

**File**: `frontend/src/Pages/Admin/Shared/AdminPagination.vue` — replace the whole file with:

```vue
<script setup>
import { computed } from 'vue'
import { router } from '@inertiajs/vue3'
import Paginator from 'primevue/paginator'

const props = defineProps({
  // A Laravel LengthAwarePaginator payload (total / per_page / current_page).
  paginator: {
    type: Object,
    default: null,
  },
})

const totalRecords = computed(() => Number(props.paginator?.total ?? 0))
const rows = computed(() => Number(props.paginator?.per_page ?? 15))
const currentPage = computed(() => Number(props.paginator?.current_page ?? 1))
const first = computed(() => (currentPage.value - 1) * rows.value)

const visible = computed(() => totalRecords.value > rows.value && rows.value > 0)

function onPage(event) {
  const target = event.page + 1
  if (target === currentPage.value) return

  const url = new URL(window.location.href)
  url.searchParams.set('page', String(target))
  router.get(url.pathname + url.search, {}, { preserveScroll: true, preserveState: true })
}
</script>

<template>
  <Paginator
    v-if="visible"
    class="admin-paginator"
    :first="first"
    :rows="rows"
    :totalRecords="totalRecords"
    :pageLinkSize="5"
    template="FirstPageLink PrevPageLink PageLinks NextPageLink LastPageLink CurrentPageReport"
    currentPageReportTemplate="{first}–{last} of {totalRecords}"
    @page="onPage"
  />
</template>
```

## Risks, tradeoffs, and open questions

**Risks**

1. **Tests empty the dev database.** Every test run wipes `products`/`catalogs`/`admins`; a browser check after a test run shows an empty admin. Re-seed before browser verification (Task 16).
2. **RoadRunner caches routes and the manifest.** Symptoms: `/admin/login` still serving the Blade page after Task 4, or the browser loading the old JS hash. Fix is always `rr reset`; also do it after Task 3 (routes) and Task 17 (deleted routes).
3. **`docker compose` picks `compose.yaml`** (no bind mount, `.env.prod`, `mariadb_test` service commented out). `exec` is safe; `up -d` would replace the live container and break your access to it.
4. **`defineOptions({ layout: AdminLayout })`** is the documented Inertia way to attach a layout to a `<script setup>` page and it is already how the current pages work — but if a page renders *without* the admin chrome after a rewrite, check that `defineOptions` was not dropped.
5. **Modal/overlay stacking.** `admin.css` uses `z-index: 1050`; PrimeVue overlays (Select panels inside `Admin/Products/Edit`) sit at `1100+`. If a dropdown renders behind a modal, raise `.admin-overlay` above it — do not lower PrimeVue's value.
6. **`AdminPagination` swaps `links` for the paginator object.** Controllers still send `links` (Laravel includes it automatically), so nothing breaks server-side; but if any other component reads `*.links`, grep for it first (`grep -rn "\.links" frontend/src`).
7. **Login-credential handling during verification.** Do not script typing the dev password into a shell or hard-code it into a test that hits a real server; the feature tests use `Hash::make` on a factory value, and the browser pass uses a hand-logged-in session.

**Tradeoffs**

- **Plain HTML controls + one stylesheet instead of PrimeVue components everywhere.** The alternative (PrimeVue `Button`/`InputText`/`Select`/`DataTable` on all ten screens) is prettier and matches `Orders.vue`, but it rewrites every template *and* every interaction surface (`useForm` bindings, `@change` handlers, file inputs) — much larger risk of behaviour regressions for a migration whose goal is "make it work". The chosen path changes only class names, so behaviour is provably unchanged; page-level PrimeVue adoption can follow screen-by-screen. PrimeVue `Paginator` *is* adopted now (Task 9), because the old component was already relying on undocumented `p-button` classes on a `<Link>`.
- **Shared `admin.css` rather than per-page scoped styles.** Ten near-identical scoped blocks were the DRY problem; one stylesheet also makes the class contract auditable with a single grep. Cost: class names are global, so prefix discipline (`admin-*`) matters.
- **Keeping `AdminLayout` as the layout mechanism** (instead of a global persistent layout in `main.js`) — smallest diff, and the layout is only used by admin pages anyway.
- **Guard on the route group** removes a per-controller line; the tradeoff is that an admin route added *outside* the group is now unguarded by construction, so Task 2's "new route" habit matters when adding routes.

**Open questions (confirm with the user before/while implementing)**

1. **Password-reset screens.** `GET /admin/password/reset` and `/admin/password/reset/{token}` still render legacy Blade (`auth.passwords.email-admin`, `reset-admin`), which `@extends('admin.admin')` — that file is deleted in Task 17, so **these two blades must be converted or re-pointed in the same task**. Decide now: (a) convert both to Inertia pages (`Admin/Password/Email.vue`, `Admin/Password/Reset.vue`) in this plan, or (b) keep them Blade but re-point `@extends('admin.admin')` to a minimal standalone layout. Option (a) is the consistent one and adds ~2 tasks; option (b) is 10 minutes.
2. **Order detail screen.** `/admin/show-order/{id}` and `PUT /admin/order` are empty stubs; the old admin had an order view. Add it (needs `app/Order.php` / `app/OrderData.php` reconnaissance first — do not invent relation names) or leave as-is?
3. **Missing "delete" stubs**: `AdminUsersController::delete()`, `AdminShippingMethodsController::delete()`, `AdminShippingMethodsController::showEditForm()/update()` are empty and unrouted. Delete the dead methods or implement them?
4. **Legacy shop-side remnants.** `resources/views/shop/order-success.blade.php`, `layouts/auth.blade.php` and `public/js/app.js` + `public/css/app.css` (Bootstrap 3 + jQuery, 1.1 MB) are outside the admin panel but are the last Bootstrap users in the app. Convert them too (follow-up) or keep?
5. **Dev credentials in tests.** Should the seeded `admin@admin.dev` / `password` fixture stay in `DatabaseSeeder` (convenient for manual verification, must never reach production), or move to a `LocalAdminSeeder`?
